# 4.5 Unit 4 Build Challenge

### @explicitHints false

## {Introduction @showdialog}

Use what you have learned in Unit 4 to build a larger Arcade game.

The new focus is **meaningful use of functions**, but your game should also use skills from earlier units.

This is a multi-day build. Keep the tutorial open as your checklist while you work.

## {Step 1 - Plan the game}

Decide what the player does, how the player wins or loses, and what gets harder as the game continues.

Choose a game idea you can realistically finish.

Before coding, identify at least **three jobs** that would make sense as functions.

Examples:

* set up a level
* create an enemy
* reset the player
* calculate a result
* search an array

## {Step 2 - Build the core loop}

Create the minimum playable version first.

Your game should include:

* event handlers for player actions or game events
* variables that change during play
* conditionals that affect what happens
* math that affects the game

Do not add extra decoration until the core game works.

## {Step 3 - Use functions meaningfully}

Move related algorithms into well-named functions.

Use functions to:

* avoid duplicated blocks
* make the main code easier to read
* break a complex task into smaller steps

At least one function should represent an important algorithm in your game.

## {Step 4 - Use an array and loops}

Include at least one array whose data is actually used by the game.

Use a loop to process or display information from an array.

Use another loop for a different purpose in the game.

## {Step 5 - Build game features}

Your project should also demonstrate earlier Arcade skills such as:

* an animated sprite
* player-controlled or player-modified variables
* meaningful conditionals
* appropriate event handlers
* increasing difficulty
* clear variable and function names

Add randomness, enemies, additional sprites, or customization where they fit your design.

## {Step 6 - Test and debug}

Play your game several times.

Ask another student to play it without explaining the controls first.

Fix problems such as:

* controls that are unclear
* code that repeats unnecessarily
* values that become impossible or unfair
* sprites that do not reset correctly
* win/lose conditions that do not trigger

## {Step 7 - Final function check}

Before you finish, inspect your functions.

For each function, ask:

* Does the name describe its job?
* Does it have one clear purpose?
* Would a parameter make it more reusable?
* Should it return a value instead of directly changing the whole program?
* Did I duplicate code that belongs in a function?

## {Finish}

Your Unit 4 project should show that functions are not just extra blocks: they are a way to organize, reuse, test, and explain program logic.
